# EcoMesh — Distributed Peer-to-Peer Disaster Relief Communication Mesh

A decentralised mesh network for disaster scenarios: every device is simultaneously an
endpoint and a router. Messages hop device to device — no internet, no cell towers, no
central server — until they reach their destination, a gateway with residual external
connectivity, or a rescue team.

## Project status

This is a **measured prototype of the routing and reliability layer**. The engine is real; the
radio is emulated.

- **Engine (Phases 1–3): done.** 52-byte wire protocol, transport interface, discovery, weighted
  routing with network-wide link-state gossip, reliability (priority queue, ACK and retry, dedup,
  bounded store-and-forward with an immediate flush when a neighbour appears), security
  (AES-256-GCM and Ed25519, both opt-in) and a SQLite log per node.
- **The one app (Phase 4): done.** The device screen (`story/node.html`) is the single front end
  and the demonstration. Each device serves it, and it becomes the survivor phone, the gateway
  view or the rescue console by role: structured SOS (need and location), "I am safe", send a
  message, the rescue team's reply, filters, message history, CSV export, a network map with link
  quality and a live panel of what the device is doing. A phone is only a screen; the engine runs
  on the laptop.
- **Simulation lab (Phase 4): done.** A FastAPI and WebSocket server (`api/`), a React website
  (`ui/`) and a virtual-time simulator (`sim/`) run many real nodes over a simulated radio. It is
  not part of the demonstration; it produced the experiment results in the report.
- **Tests:** 334 automated tests (`python -m pytest -q`) plus scripted browser checks of the device
  screens (`docs/testing/device_walkthrough.cjs`) and of the lab website (`docs/testing/ui_walkthrough.cjs`).

**Not built, stated openly:** a real radio (devices talk over TCP, but only to the neighbours a
config file allows), a phone application, and per-pair keys (one shared key protects the mesh).

## Run the demo

```
pip install -r requirements.txt
python -m story.local            # five devices on this machine; add --no-browser to skip opening tabs
```

Open `http://127.0.0.1:8101` (survivor) and `http://127.0.0.1:8105` (rescue console). To open the
survivor screen on a phone on the same Wi-Fi, add `--phone`. For two laptops, see
[`docs/DEMO_SCRIPT.md`](docs/DEMO_SCRIPT.md), which also holds the five-minute script.

## Run the simulation lab (optional)

```
cd ui && npm install && npm run build && cd ..
python -m api.server            # http://127.0.0.1:8000  (lab website + API + WebSocket)
python -m sim.scenarios --scenario hopcount_vs_weighted --runs 20
```

## Running the tests

```
pip install -r requirements.txt
python -m pytest -q
npm install --no-save puppeteer-core
node docs/testing/device_walkthrough.cjs     # starts the five devices itself; needs Chrome
```

## Branch layout

Each phase lives on its own branch, inheriting everything before it rather than merging
back: `develop` (Phase 1) → `develop_2` (+ Phase 2) → `develop_3` (+ Phase 3) →
`develop_4` (+ Phase 4) → `develop_5` (+ report and evaluation) → `develop_6` (final app, tests and
documents) → `develop_7` (changes after the evaluation: nine SOS options, voice input, updated
report, poster and documents). See `CONTRIBUTING.md` for commit conventions.
