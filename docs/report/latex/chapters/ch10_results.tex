\subsection{Functional Results}
Of the 68 requirements, \NAuto\ are verified by automated tests alone, \NAutoUI\ by automated tests plus a manual check of the screen, \NInspect\ by code inspection, \NManual\ by manual check only, and \NPartial\ are partial (Table~\ref{tab:fr}). The three stories that matter most were demonstrated on real devices: an SOS reaches the rescue device over several hops; the network re-routes around a failed relay; and a message with no route is held and later delivered.

\subsection{Performance Results}
Table~\ref{tab:kpival} collects the measured KPIs: \CollDel\,\% delivery on a 40-node mesh at 20\,\% loss with failures; an SOS median latency \SosAdv$\times$ lower under load; live SOS delivery in a median of 47\,ms on loopback; relay failover in about 4\,s; held messages flushed in about 4.5\,s.


\subsection{Comparison with Existing Systems}
We did not run other systems, so the comparison is limited to documented properties (Table~\ref{tab:compare1}) and to the one baseline that can be measured fairly, hop-count routing on identical seeds (\HopW\,\% against \HopH\,\% in the designed topology). We make no claim about the delivery of Bridgefy, Briar, Meshtastic or Serval, which publish no comparable measurements.

\subsection{Discussion of Findings}
Hop count is a poor proxy for delivery, and the cost is large when it is wrong: a weak shortcut loses almost half the traffic under hop count and almost none under the weighted cost, with no change to topology or traffic. Timer constants shape the results: recovery clusters at the heartbeat timeout and convergence at multiples of the gossip interval, so those targets are properties of constants rather than algorithms, which tells us exactly what to tune. Loss is paid for in tail latency: delivery stays high to 30\,\% loss, but each lost ACK costs a timeout, so medians move from milliseconds to seconds. Priority matters only under contention: on an idle network SOS and routine traffic are equally fast, and the advantage appears once a link queues, which is the disaster condition. Testing found real defects in code we believed finished (Section~\ref{sec:defects}).

\subsection{Practical Applicability}
A deployment needs devices running the node program, a topology (or multicast discovery), a gateway or rescue device and a shared network segment. It is usable today as a campus, hospital or building safety system on existing laptops, and as the reference implementation of a protocol whose transport can later be Bluetooth Low Energy or Wi-Fi Direct. Without a radio transport it is not yet a phone-to-phone application, which is the main gap to deployment.
