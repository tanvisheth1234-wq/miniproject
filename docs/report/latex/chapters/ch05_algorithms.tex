\section{Algorithm Design and Data Structures}
\label{ch:alg}

\subsection{Identification of Critical Operations}
Ten operations decide correctness and performance: (1) neighbour discovery and link quality; (2) link-state dissemination; (3) least-cost routing; (4) the per-packet forwarding decision; (5) priority scheduling; (6) duplicate suppression; (7) send, acknowledge and retry; (8) bounded store-and-forward; (9) encryption and signing; (10) resolving \texttt{RESCUE\_\_}. They are Algorithms 1--10 of the Phase~II \emph{Design of Algorithms}, shown here as implemented.
\subsection{Algorithm Design}
\label{sec:algdesign}
\noindent\textbf{A1 Discovery and link quality.}
\begin{lstlisting}
every 3 s: broadcast HELLO(role, public_key)                      // ttl = 1
on HELLO from p:  new <- table.update(p);  if new: on_peer_up(p)
    q <- hellos_received / hellos_expected   in a 20-slot window    // in [0,1]
    if |q - last_reported| >= 0.1: report q                         // avoids recomputing on noise
every 1 s: for p silent > 10 s: remove p; on_peer_down(p)
\end{lstlisting}
A new neighbour is scored over the HELLOs \emph{due} so far, otherwise every fresh link would look lossy.

\needspace{5\baselineskip}\noindent\textbf{A2 Link-state with re-flooding.}
\begin{lstlisting}
every 5 s: seq++; send report(origin=me, seq, [(p, q, failures, role, key) for p in neighbours]) to each neighbour
on report(origin, s, entries) from sender:
    if origin = me or s <= seq_seen[origin]: return                  // stale or own: stop
    seq_seen[origin] <- s;  replace origin's outgoing edges with entries;  learn roles and keys
    if changed: invalidate route cache
    forward report unchanged to every neighbour except origin and sender   // controlled re-flooding
\end{lstlisting}
Without re-flooding a node knows only its neighbours' neighbours; sequence numbers admit each report once per link, so flooding terminates.

\needspace{5\baselineskip}\noindent\textbf{A3 Dijkstra and the cost function.}\label{sec:cost}
\begin{lstlisting}
cost(u->v) = 1 + 5 * (1 - q) + 3 * f        // f = ACK timeouts on the link in the last 60 s
dist[src] <- 0; heap <- {(0, src)}
while heap: (d,u) <- pop_min; if u visited: continue; mark u
    for (v, e) in graph.neighbours(u): if d + cost(e) < dist[v]: dist[v] <- d + cost(e); prev[v] <- u; push
next_hop(dst) = path[1] of the cached shortest path, or none (=> store-and-forward)
\end{lstlisting}
\textbf{Derivation of the coefficients.} The base 1 is the per-hop penalty; it keeps every weight positive (Dijkstra's condition) and prefers fewer hops between equal links. The term $5(1-q)$ makes loss expensive: a link delivering 40\,\% of its HELLOs costs $1+5(0.6)=4.0$, more than two clean hops (2.0) or three (3.0), which is exactly where minimum-hop routing errs. The term $3f$ is steeper than the estimated-loss term because an ACK timeout is \emph{observed} failure: one adds the cost of three extra clean hops, and it applies at once so the retry avoids the failing link.

\needspace{8\baselineskip}\noindent\textbf{A4 Packet handling.}
\begin{lstlisting}
on packet p from link sender s:
    if not parse_ok(p) or p.type not in {DATA, ACK}: drop
    for_me <- p.dst = me or (p.dst = RESCUE__ and my role in {GATEWAY, RESCUE})
    key <- (type, msg_id) if for_me else (type, msg_id, attempt)     // a retry crosses relays that saw the original
    if dedup.seen_before(key): drop(duplicate); re-ACK if for_me; return
    if for_me: verify signature; decrypt; log; ACK if needs_ack; deliver
    elif ttl <= 0: drop(ttl_expired)   elif me in path: drop(loop)   elif no next_hop: drop(no_route)
    else: ttl--; hop_count++; path.append(me); queue.push(p, priority)            // A5
\end{lstlisting}
The key includes the \emph{type}, because an ACK carries the id of the DATA it acknowledges (a bug found in integration), and at relays the \emph{attempt}, so a retransmission is forwarded; the destination ignores the attempt and sees each message once. Only the originator retains (A8).

\textbf{A5 Priority scheduling.} \texttt{push} inserts (priority, timestamp, counter) into a binary heap and \texttt{pop} returns the highest priority, then the oldest; the counter prevents ties from comparing packets. Applied at \emph{every} hop, an SOS overtakes routine traffic repeatedly along the route. \textbf{A6 Dedup.} A hash map of keys to first-seen time, pruned after 300\,s. \textbf{A7 Send, ACK, retry.} A timed-out packet with fewer than 3 attempts gets a failure recorded on its link (cost $+3$), a recomputed route and a resend; after 3 attempts it moves to store-and-forward (Figure~\ref{fig:flowsend}). \textbf{A8 Bounded store-and-forward.} \texttt{enqueue} evicts, when over 500 messages, the one with the largest (priority value, age), i.e.\ the lowest priority and oldest; \texttt{expire} drops anything older than 1800\,s regardless of priority; the flush (every 10\,s) sends each message whose destination now has a route. \textbf{A9 Security.} Send encrypts with a random nonce and signs the identity bytes; receive verifies against the sender's known key, then decrypts; either failure drops the packet. \textbf{A10 \texttt{RESCUE\_\_}.} One Dijkstra run, then the nearest reachable node whose role is GATEWAY or RESCUE; none reachable means store-and-forward (Figure~\ref{fig:flowroute}).

\subsection{Algorithm Selection and Justification}
Flooding delivers but its message count grows with the square of the node count and collapses a mesh under load. Bellman--Ford ($O(VE)$) and A* (needs a geometric heuristic) bring nothing here. Dijkstra with a binary heap is correct for non-negative weights in $O((V+E)\log V)$, and the weighted cost avoids the lossy shortcuts hop count picks (Chapter~\ref{ch:perf}). A heap rather than a sorted list or FIFO gives $O(\log n)$ priority order; a hash set gives $O(1)$ duplicate checks.

\subsection{Space Complexity Analysis}
The graph needs $O(V+E)$, the dedup set grows with traffic in its 300\,s window, the retention queue holds at most 500 packets and Dijkstra needs $O(V)$ extra; only the on-disk SQLite log is unbounded.
\subsection{Optimization Opportunities}
\label{sec:opt}
Per-destination cache invalidation and incremental shortest paths; multipoint relays to cut redundant report copies~\cite{rfc3626olsr}; short retention at relays; batched SQLite commits; and the timer changes the measurements point to (Chapter~\ref{ch:perf}).
